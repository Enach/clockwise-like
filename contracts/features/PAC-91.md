## 2. nginx: framability per request (clockwise-like)

### 2.1 Inputs

- **Raw path**: the request target exactly as received (nginx
  `$request_uri`: no decoding, no slash merging, no dot-segment
  resolution), cut at its first `?`. The query is never inspected.
- **Normalised path**: nginx `$uri` (decoded, slashes merged, dot segments
  resolved; no query), as today.

### 2.2 Rule

A response is **framable** iff both hold:

1. the normalised path matches `^/book/[^/]+/?$` (today's rule, unchanged);
2. the raw path is `/book/`, then one **plain segment**, then an optional
   `/`, and nothing else. A plain segment is one or more characters, none
   of them `/`, that
   - contains no `%2F` / `%5C` escape, compared case-insensitively
     (`%2f`, `%5c` too), and
   - is not a dot segment in any spelling: `.`, `..`, and any mix of `.`
     and `%2E`/`%2e` of length one or two (`%2e`, `.%2e`, `%2E%2e`, ...).
     A segment that merely contains dots (`..x`, `a.b`) is plain.

Matching of `/book/` itself is case-sensitive (as today): `/BOOK/x` is not
framable.

### 2.3 Outputs (unchanged values, new decision)

| Framable | `Content-Security-Policy` | `X-Frame-Options` |
|---|---|---|
| yes | the shared policy + `frame-ancestors *` | absent |
| no | the shared policy + `frame-ancestors 'none'` | `DENY` |

Every other CSP directive and every other security header is identical on

## 3. Web app (smart-calendar-flow)

### 3.1 One link target

`src/lib/framing.ts` (new) exports:

```ts
/** Target of every link that leaves a possibly framed page for another Paceday page (spec D-2, owner OQ-1). */
export const TOP_LEVEL_LINK_TARGET = "_top";
/** True when this window is not the top-level browsing context. Never reads the embedder. */
export function isFramed(): boolean;
```

`isFramed()` compares the app's own window with the top-level window and
reads nothing else from it, so it cannot throw across origins. Tests stub
it (`vi.mock("@/lib/framing")` or `vi.spyOn`), never jsdom's `window.top`
alone.

Answering OQ-1 "new tab" changes `TOP_LEVEL_LINK_TARGET` to `"_blank"` (one
line; browsers imply `noopener` for `_blank`) and AC-4's expected outcome.
No other code changes.

### 3.2 The booking page's links

The three "back to Paceday" links in `src/pages/PublicBooking.tsx` (main
:249, :277, :360; PAC-88 :355, :383, :487) become anchors to `/` with
`target={TOP_LEVEL_LINK_TARGET}`. React Router's `<Link>` with a non-`_self`
target already lets the browser navigate, so either `<Link>` or `<a>` is
acceptable; the rendered `href` is `/` and the rendered `target` is the
constant's value. Accessible names unchanged ("← Back to Paceday",
"paceday").

### 3.3 The frame guard

A component mounted **inside `BrowserRouter` and above `AuthProvider`** in
`src/App.tsx` (the only placement that satisfies spec D-7: `AuthProvider`
probes `/api/auth/me` on mount for every route), which on every render:

- if `isFramed()` is false: renders its children (the app as today);
- if framed and the current location matches the router's `/book/:slug`
  (the same pattern and matching the `<Route>` uses, via `matchPath`):
  renders its children;
- otherwise renders only the frame notice (section 4), synchronously on
  that render: no effect, no state round-trip, so no route component
  renders first and no child `<Navigate>` fires.

`ToastViewport` and Sentry are unaffected. The notice copy is the
implementer's (spec D-5) and passes `make design-check`; it names Paceday
and has exactly one link.

## 7. Rejected

- **Raw-path rule alone, dropping the `$uri` check.** Strict enough on its
  own, but keeping today's normalised check costs nothing and keeps every
  existing `partc_test.go` row meaningful.
- **Decoding the raw path once and comparing it to `$uri`.** Rejects too
  little (`%2e` handling differs) and is harder to state as a table.
- **Inspecting the whole `$request_uri`.** Refuses real embeds whose
  tracking parameters carry encoded URLs (section 2.4, framable rows).
- **Guard implemented in an effect.** Children's effects run first, so
  `RequireAuth`'s `<Navigate>` and `/logout`'s sign-out would already have
  run (spec challenge, blocking 4).
- **Changing the file server** (spec D-6).
