## 1. Approach

One storage entry point, `storage.EraseAddress`, runs the contract's §3.3
transaction verbatim: a settings/preflight statement, the input's database
lowercasing, the account check, discovery of every matching row into a
temporary table with no row lock, the counts, then (erasure only) the lock
phase in §6.1's order with each row re-checked under its lock, and the
address-free audit record. Every statement is a constant assembled from fixed
fragments (`eraseMatch`, `eraseJSONMatch`); the address travels only as a bind
(`$1` = Go lowercasing, `$2` = the database's `lower()`, input `$1` of
`input_lower`), and the pool is always on pgx's `QueryExecModeDescribeExec`
(B-1). The command (`cmd/paceday-operator/erase_address.go`) parses flags,
standard input and validity before any connection (exit 2), migrates like the
PAC-71 subcommands (erasure only), checks the maintenance lock and the schema,
then prints counts, account ids and the record id, and errors by class only.

The bound is enforced three ways: the client's context deadline (fixed at the
run's start), the transaction-local `statement_timeout`/`lock_timeout` set to
the bound by the first statement, and (N-1) re-armed to the time left before
every lock-phase statement, so a contended lock-phase statement is ended by
the server by the deadline even with the client gone. Three live writers were
aligned to the tool's lock order (L-1 invitation expiry sweep by id, L-2
keyed-create cleanup by `(owner, key "C")`, L-3 Manager confirm in byte order
with a `FOR KEY SHARE` existence read).

## 4. What the AC-11b work found (contract amended)

- **W19, W26 keyed retries do not wait** on the key's unique slot: the replay
  is decided on the resolution's snapshot, so while the tool is held a retry
  replays the not-yet-erased row; after the commit it gets key reused. Only
  the create transaction reached with the key being cleared (the R3 race path)
  waits, then ends in `ErrLinkCreateConflict`. Recorded as a stage-4
  amendment to md §6.3 / D-2 / §14.
- **W17 "writer first"** cannot contend: `ON CONFLICT DO NOTHING` on a new
  key locks no existing row; the test asserts the tool completes.
- "Writer first" uses the real writer held by an existing seam
  (`InstallAfterTeamLock`, `InstallAfterLinkInviteLock`,
  `InstallAfterLinkPatchUpdate`, `InstallAfterBookerErasureRecheck`,
  `InstallBeforeLinkCreateCommit`, `InstallAfterBookingInsert`) or inside an
  outer transaction kept open; W9 and W27 (functions that take a `DBTX` and
  open their own transaction) are **emulated** by their L-1/L-2 statement in
  an outer transaction.

## 8. Deviations

1. **D-1, the lock-phase budget is re-armed before every lock-phase
   statement, not once.** N-1 asks to set it "right before `lock_teams`";
   since the timers restart per statement, a single re-arm would let a later
   statement run up to that budget past the deadline. It is re-armed before
   each statement of the phase (13 extra round trips, included in the
   measured lock-hold time), less a 20 ms margin for the round trip before
   the next statement starts. Recorded in the contract amendment.
2. **D-2, exit class `interrupted`** (SIGINT/SIGTERM), not in md §2.6's list.
3. **D-3, the `auto_explain` preflight when the module is not loaded**: a
   placeholder set by `ALTER DATABASE`/`postgresql.conf` is not listed in
   `pg_settings`, so it does not refuse (an unloaded module logs nothing); a
   listed value that is not a number refuses.
4. **D-4, AC-9's (h) is on its own team** (see §3 Fixtures), and (f) is
   stored normalised (`pat@ext.example`): the T2 CHECK refuses
   `PAT@ext.example` since migration 041.
5. **D-5, the database half of the rule has no behavioural witness on the
   production image**: over every scalar value, no code point is lowercased by
   `lower()` on `postgres:16.15-alpine` (musl, `en_US.utf8`) and left alone by
   Go (checked on the development container: 0 such code points; 69 the other
   way, e.g. circled letters U+24B6–U+24CF, which only Go lowercases). The half
   is proven on an ICU `tr-TR` database instead (`TestPAC134_BothLoweringsDecide`).
6. **D-6, `testdb.CreateWithOptions`** added besides the contract's C-locale
   option, for that ICU database.
7. **D-7, AC-11b W9 and W27 "writer first" are emulated** (§4).
8. **D-8, AC-22b is a build-tagged test** (`-tags pac134perf`) rather than an
   environment-gated `t.Skip`, so no skip without an issue appears in the
   default suite.
9. **D-9, tests written alongside the code**, not red-first; that they test the
   stated rules is shown by the mutations in §6.

## 8a. Independent review of #326 (APPROVE at `b31bf88`): follow-ups applied

All nine deviations were accepted. The follow-ups, each recorded here and,
where behaviour or text changed, as a dated amendment in the contract md
("Amendments after the independent review of #326") and yaml
(`stage4Amendments`):

1. **Interrupts did not cancel the server's statement.** pgx's default
   context handler closes the socket and sends its cancel request from a
   goroutine afterwards, which a process that exits at once (the command
   after Ctrl-C) never runs; a backend in a lock wait then kept the run's
   locks until its own timeout (reviewer's probe). The command's pool now
   uses `pgconn.CancelRequestContextWatcherHandler` (`OpenNoMigrateDescribeExec`):
   the cancel request is sent when the context ends, before the command
   returns. An interrupt is classified `interrupted` even though the server
   answers 57014. Tests: `TestPAC134_InterruptReleasesLocksAtOnce` (in
