## 1. Approach

Pending invitations stay in `scheduling_link_hosts` as rows with
`user_id IS NULL` and `invitee_email` set (contract md §4.0, alternative 1
rejected there). Every inviter-side path decides by address only, under the
link's lock: the single invite (`storage.InviteLinkAddressCtx`) and the list
(`setCoHostList`) read the link's rows joined to `users` **by `user_id`
only**, the owner's address **by the owner's id**, and have the database
`lower()` the typed addresses (`lowerAll`, a statement that reads no table).
The address is matched to an account only on the invitee side
(`inviteeHolder`: the caller's own row, standing `domain_confirmed`, no other
carrier of the address), for the invitation list, accept, decline and leave.
The delete erases the link's pending invitations in its own write.

### The challenger's two test-hardening points (AC-6)

- **N-7** (`pac149UsersByIDOnly`). For every recorded statement whose SQL
  references `users`: no email column is compared with anything (`x.email =`,
  `lower(x.email) =`, `= lower(x.email)`, `LIKE`, `ILIKE`, `IN`, `~`), and
  every `FROM`/`JOIN users [alias]` is restricted by `alias.id` (or bare `id`)
  equal to a bind argument or to `user_id` / `owner_user_id` qualified by an
  alias of `scheduling_links` / `scheduling_link_hosts` in the same statement.
  So `JOIN users u ON lower(u.email) = lower(h.invitee_email)` and a join to
  `user_identities` are both caught. `TestPAC149_N7_UsersByIDOnlyRule` pins the
  predicate on 13 statements (5 allowed, 8 refused).
- **N-8** (`pac149ArgText`). Every argument is searched as `fmt` prints it, as
  its `driver.Valuer` value (so `pq.Array`'s encoded `{…}` text), as raw bytes,
  and element by element for `[]string`/`*[]string`. The B-5 check (no
  statement referencing `users` carries the typed address or its `lower()`)
  and the tokenising run on that text.

## 8. Deviations

1. **D-1, an edit outside `allowedPaths`: `backend/storage/session.go`.**
   The contract (md §6) requires the recorder to see every statement of the
   request "on the pool and inside the write transaction" through a wrapper of
   the Querier handed to storage. The link-write transaction and the PAC-71
   re-check are opened in `withLinkWriteTx`/`withGenerationTx`, which live in
   `session.go`; they now pass `recordingTx(db, tx)`, which is `tx` itself
   unless the handler's `db` is a test's recorder. Production behaviour is
   unchanged.
2. **D-2, other test files outside the named list**:
   `api/pac71_session_test.go`, `storage/pac71_guarded_writes_test.go`,
   `storage/pac148_migration_test.go` (§4). Each is a fixture or harness
   adaptation; none changes what the test protects.
3. **D-3, PAC-112 AC-16's second half changes outcome.** Spec §2.4 lists
   AC-16 as "unchanged in outcome", but spec §3.2 rule 1 (own_address by
   comparison with the owner's stored address, "not by a lookup") makes an
   owner whose own address is held unconfirmed get `own_address` instead of
   `not_added`. The rule was followed; the test was updated with a comment.
4. **D-4, the count step is computed in Go.** Contract md §2.6 lists "count"
   among the inviter-side statements; the implementation counts the non-owner
   rows from the entries read it already made under the lock, one statement
   fewer, identical for every new address.
5. **D-5, AC-9's emptiness half at the storage layer** uses
   `FirstNonEmptyKind` (the function PAC-71 rule (b) calls at sign-in); the
   sign-in half is the API test `TestPAC149_AC9_LegacyWithInvitationBinds`.
6. **D-6, no separate plan stage; tests written alongside the code.** That
   they fail for the stated reason is shown by the mutations in §6, not by a
   red run before any implementation (the pre-PAC-149 code does not compile
   against the new storage API).
7. **D-7, `RespondToHostInvite`/`RemoveLinkHost` (no lock) carry the full
   invitee rule**, and the `…Locked` request-path versions call them after the
   link lock, rather than the rule living only in the locked functions. The
   plain functions were already exported and used by fixtures.
